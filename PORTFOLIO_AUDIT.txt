1. PROJECT PURPOSE, TECHNOLOGIES & CURRENT FUNCTIONALITY
--------------------------------------------------------------------------------
1.1 Project Purpose:
The project is a multi-tier academic and professional portfolio created by Krina
Bhuva for the Advanced Web Development (AWD) course (Practicals 4 through 11).
It serves a dual purpose:
  a) A professional developer portfolio showcasing bio, skills, featured projects,
     contact details, and a live GitHub repository feed.
  b) A laboratory testbed for progressive web engineering concepts: REST API design
     (P4), MongoDB/Mongoose integration (P5), React CRUD frontend (P6), JWT Bearer
     authentication (P7), React code-splitting/lazy-loading (P8), in-memory cache
     optimization with node-cache (P9), asynchronous decoupled event notification
     with Node.js EventEmitter (P10), and multi-container Dockerization (P11).

1.2 Technology Stack:
  - Frontend Core: React 19.2.7, React DOM 19.2.7, React Router DOM 7.18.1.
  - Frontend Build & Dev: Vite 8.1.4, @vitejs/plugin-react 6.0.3, Oxlint 1.71.0.
  - Frontend Styling: Vanilla CSS with custom properties (CSS variables), glassmorphism,
    responsive media queries, dark/light mode toggle, and an interactive HTML5
    Canvas simulation (DigitalMindscape).
  - Backend Core: Node.js 22.15.0 (ES Modules, "type": "module"), Express.js 4.19.2.
  - Backend Storage: MongoDB 7.0 via Mongoose 8.5.1 ODM.
  - Authentication: JSON Web Tokens (jsonwebtoken 9.0.3) + bcryptjs 3.0.3 password hashing.
  - Performance & Architecture: node-cache 5.1.2 (in-memory caching with TTL = 60s),
    native Node.js EventEmitter (decoupled async notification worker).
  - Containerization: Docker (node:20-alpine base images) & Docker Compose (v2).
  - Testing & Verification: Jest 30.5.2, Supertest 7.3.1 (installed in server),
    custom CLI benchmark scripts (test-performance.js, test-practical10.js,
    test-api-verification.js).

1.3 Current Functionality:
  - Homepage (/): Displays hero greeting, profile photo, bio cards, areas of
    interest, strengths, and skills grid.
  - Projects Page (/projects): Displays static featured projects list and fetches
    live GitHub repositories via GitHub REST API with real-time search filtering.
  - Contact Page (/contact): Controlled input demonstration with live two-way
    binding display and character counter.
  - Task Manager Page (/tasks, /task-manager): Full CRUD interface structure (add,
    toggle complete, inline edit, delete with modal, filter tabs, toast alerts).
  - Backend REST API: Full CRUD endpoints for tasks (/tasks), user authentication
    (/register, /login, /me), cache monitoring (/debug/cache), and cache benchmarking
    (/debug/cache/benchmark).

4. DISCOVERED ISSUES CATALOG
--------------------------------------------------------------------------------
ISSUE #1: Frontend TaskManager Fails with HTTP 401 Unauthorized
  - Severity: HIGH
  - Affected Files: src/api.js, src/components/TaskManager.jsx, server/routes/taskRoutes.js
  - Evidence: TaskManager displays: "Not authorized, token missing or invalid format (Bearer token required)".
    `server/routes/taskRoutes.js` enforces `router.use(protect)`. `src/api.js` sends requests
    without an `Authorization` header.
  - Likely Cause: Practical 7 backend introduced JWT authentication, but Practical 6 frontend
    was never updated with a login interface or an Axios request interceptor to store and
    attach JWT tokens.

ISSUE #2: Missing `npm test` Script in Backend and Root manifests
  - Severity: HIGH
  - Affected Files: server/package.json, package.json
  - Evidence: `npm test` outputs: `npm error Missing script: "test"`.
  - Likely Cause: Testing scripts were named `test:cache` and `test:events`. Standard Jest
    test runner script was never defined.

ISSUE #3: `server.js` Lacks Module Export and Executes Top-Level Side Effects
  - Severity: HIGH
  - Affected Files: server/server.js
  - Evidence: `server.js` ends with `app.listen(PORT, ...)` without `export default app`.
    `connectDB()` is executed immediately on line 15.
  - Likely Cause: Monolithic server setup designed strictly for CLI launch (`node server.js`),
    preventing programmatic import by Supertest or CI test suites.

ISSUE #4: Severe Dependency Security Vulnerabilities (Root & Backend)
  - Severity: HIGH (1 Critical, 11 High across project)
  - Affected Files: package.json, server/package.json, package-lock.json
  - Evidence: `npm audit` reports critical IP spoofing in `proxy-addr` (1.1.0 - 2.0.7),
    multiple prototype pollution and SSRF advisories in `axios` (1.0.0 - 1.19.0),
    DoS in `body-parser` (<1.20.9), and DoS in `brace-expansion`.
  - Likely Cause: Outdated transitive dependencies locked in `package-lock.json`.

    `dotenv: "^17.4.2"`, and `nodemon: "^3.1.14"`. None of these packages are imported

6. MISSING FEATURES, UI/UX DEFICIENCIES, RESPONSIVE & DEPLOYMENT RISKS
--------------------------------------------------------------------------------
6.1 Missing Features:
  - No frontend login/register forms or modal to authenticate users with the backend.
  - No automated CI/CD pipeline (.github/workflows/ci.yml) to guard against regressions.
  - No Jest/Supertest automated unit/integration test suite configured for `npm test`.
  - No backend email or database persistence for contact form inquiries.

6.2 UI / UX Deficiencies:
  - Hero header has no Call-To-Action buttons, leaving a visually empty area below the intro.
  - Clicking footer quick links while on the `/contact` page does not navigate back to Home.
  - Browser console logs a 404 error on initial load due to missing favicon.svg.
  - Light mode styling is partially implemented; some card borders and subtle text elements
    exhibit lower contrast in light mode compared to dark mode.

6.3 Responsive Issues:
  - Very small mobile screens (< 360px): TaskManager header badge and filter tabs can wrap
    into multiple lines, slightly compressing the task input row.
  - Contact page cards have fixed top padding (`paddingTop: '120px'`) inline, which can
    cause vertical overflow on short mobile landscape viewports.

6.4 Deployment Risks:
  - CI Environment Failure: GitHub Actions runners do not run MongoDB by default. Any test
    that attempts an unmocked live MongoDB connection or calls `server.js` without
    `NODE_ENV=test` guards will abort the CI job.
  - Port Collisions in Production: Running both Vite dev server and Express on default ports
    without reverse proxying can lead to CORS issues if `VITE_API_URL` is misconfigured.
